Solving the Ebola SIRD System in R

deSolve is the standard R package for solving initial value problems in ordinary differential equations. It provides a unified interface to dozens of numerical solvers and is the computational engine behind the epidemic projections on this portal.

1. The Three-Step Pattern

Every deSolve model follows the same recipe:

  1. Define the derivative function — a function that takes the current state and parameters and returns the rate of change for each compartment.
  2. Set initial conditions — the state of every compartment at time zero.
  3. Call ode() with the initial state, the time vector, the derivative function, and the parameters.

2. The SIRD Derivative Function

For Ebola, the derivative function encodes the four ODEs of the SIRD model:

library(deSolve)

sird_model <- function(time, state, parms) {
  with(as.list(c(state, parms)), {
    N  <- S + I + R + D
    dS <- -beta * S * I / N
    dI <-  beta * S * I / N - (gamma + mu) * I
    dR <-  gamma * I
    dD <-  mu * I
    list(c(dS, dI, dR, dD))
  })
}

The function returns a list whose last element is a vector of derivatives. deSolve uses this vector to advance the state forward in time.

3. Setting Up the Initial State

On day 1 of the outbreak, the number of infectious individuals is known from the data. The initial Susceptible, Recovered, and Deceased values are derived from that:

state0 <- c(
  S = 20000000 - 5,   # 20 million population at risk
  I = 5,              # 5 confirmed Ebola cases on day 1
  R = 0,
  D = 0
)

params <- c(beta = 0.42, gamma = 0.13, mu = 0.05)
times  <- 0:150

4. Running the Solver

out <- ode(
  y     = state0,
  times = times,
  func  = sird_model,
  parms = params
)

head(out)
#   time        S       I     R       D
# 1    0 19999995       5     0       0
# 2    1 19999995.3 ...   ...     ...

The result is a data frame with one row per time point and one column per compartment. It is the full trajectory of the outbreak over the simulated period.

5. Choosing the Right Solver

deSolve includes several solvers. Choosing the right one depends on the properties of the system:

  • lsoda — the default; auto-switches between stiff and non-stiff methods; recommended for epidemic models.
  • vode — variable-coefficient solver, good for long integrations.
  • ode45 — classic non-stiff Runge–Kutta; fast but fragile on stiff systems.
  • radau — implicit solver for very stiff systems with large compartment scale differences.

For the Ebola portal, lsoda is used because it balances stability and speed even when the Susceptible population is 20,000,000 and Infectious is 5.

6. Calibrating the Model with optim()

deSolve solves the equations once the parameters are known. But how do we find the parameters in the first place? We pair deSolve with optim(), an R function that minimizes a user-defined objective function.

The objective compares the model's predicted cumulative cases (\(\text{I} + \text{R} + \text{D}\)) against the observed cumulative cases, and returns the sum of squared errors:

sird_objective <- function(par) {
  beta  <- exp(par[1])
  gamma <- exp(par[2])
  i0    <- exp(par[3])
  mu    <- 0.05

  state0 <- c(S = 2e7 - i0, I = i0, R = 0, D = 0)
  out <- tryCatch(
    ode(state0, times, sird_model,
        c(beta = beta, gamma = gamma, mu = mu)),
    error = function(e) NULL
  )
  if (is.null(out)) return(1e12)

  predicted <- out$I + out$R + out$D
  sum((predicted - observed_cases)^2)
}

fit <- optim(
  par    = log(c(0.5, 0.1, 5)),
  fn     = sird_objective,
  method = "L-BFGS-B",
  lower  = log(c(0.01, 0.01, 1)),
  upper  = log(c(5.0, 1.0, 1000))
)

Two crucial details here:

  • Logarithmic reparameterization: optim() works with log()-scaled parameters so that all proposals are automatically positive. This is essential because all epidemiological rates are positive by definition.
  • tryCatch() wrapper: ode() can fail if the parameters are physically impossible (e.g., a negative recovery rate). The wrapper returns a large penalty value so optim() avoids that region of parameter space instead of crashing.

7. Full-Fit and Projection Workflow

In practice, the model is fitted in three stages:

  1. Training: Fit the parameters to the first 80% of the observed data.
  2. Full fit: Re-solve over the entire observed window to plot the model against all data.
  3. Projection: Anchor a new ode() call at the last observed state and integrate forward for the projection horizon.

Anchoring the projection at the last observed state is critical. If you simply continue integrating from the model's fitted state on the last training day, the projection can jump discontinuously at the boundary. Anchoring fixes this and guarantees that the projected curve starts exactly where the observed curve ends.

8. Practical Tips

  • Always inspect the return object — NA rows indicate the solver failed.
  • Wrap calls in tryCatch(), especially inside optim().
  • Bound parameters tightly with lower and upper.
  • Normalize errors by the number of observations so RMSE and MAE are interpretable.
  • Split the data into training and testing windows before fitting, to validate the projection.
