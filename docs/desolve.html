Solving the Intervention-Aware SIRD System in R

deSolve is the standard R package for solving initial value problems in ordinary differential equations. It provides the computational engine behind the epidemic projections on this portal, including the time-varying transmission rate that reflects interventions.

1. The Three-Step Pattern

Every deSolve model follows the same recipe:

  1. Define the derivative function — takes the state and parameters, returns the rate of change for each compartment.
  2. Set initial conditions — the state of every compartment at time zero.
  3. Call ode() with the initial state, time vector, derivative function, and parameters.

2. The SIRD Derivative Function with Interventions

For Ebola, the derivative function encodes the four ODEs and the time-varying transmission rate:

library(deSolve)

sird_model <- function(time, state, parms) {
  with(as.list(c(state, parms)), {
    N <- S + I + R + D
    
    # Time-varying transmission: beta0 before tau, decaying afterward
    beta_t <- beta0 * exp(-k * max(0, time - tau))
    
    dS <- -beta_t * S * I / N
    dI <-  beta_t * S * I / N - (gamma + mu) * I
    dR <-  gamma * I
    dD <-  mu * I
    list(c(dS, dI, dR, dD), beta_t = beta_t)
  })
}

Notice that the function returns both the derivatives and the current value of β(t). This allows the fitted trajectory to be plotted, so the analyst can inspect when the intervention effect became significant.

3. Setting Up the Initial State

state0 <- c(
  S = 20000000 - 5,
  I = 5,
  R = 0,
  D = 0
)

params <- c(
  beta0 = 0.40,   # transmission before interventions
  gamma = 0.10,   # recovery
  mu    = 0.15,   # mortality
  k     = 0.02,   # intervention decay
  tau   = 20      # intervention start (days since first case)
)

times <- 0:150

4. Running the Solver

out <- ode(
  y     = state0,
  times = times,
  func  = sird_model,
  parms = params
)

The result is a data frame with one row per time point and columns for each compartment plus β(t). It is the complete trajectory of the outbreak.

5. Choosing the Right Solver

  • lsoda — default; auto-switches between stiff and non-stiff; recommended for epidemic models with time-varying parameters.
  • vode — variable-coefficient, good for long integrations.
  • ode45 — classic non-stiff; can fail on stiff systems.
  • radau — implicit solver for very stiff systems.

For Ebola, lsoda is used because the Susceptible population (20,000,000) and the Infectious population (single digits) differ by seven orders of magnitude, and the intervention effect introduces additional time-scale variation.

6. Calibrating the Model with optim()

The parameters β₀, γ, μ, k, and τ must all be estimated from the data. This is done by minimizing the sum of squared errors between observed and predicted cumulative cases:

sird_objective <- function(par) {
  beta0 <- exp(par[1])
  gamma <- exp(par[2])
  mu    <- exp(par[3])
  k     <- exp(par[4])
  tau   <- exp(par[5])
  i0    <- exp(par[6])

  # Guard against pathological values
  if (beta0 > 5 || gamma > 2 || mu > 2 || k > 1 || tau > 100) return(1e12)

  state0 <- c(S = 2e7 - i0, I = i0, R = 0, D = 0)
  out <- tryCatch(
    ode(state0, times, sird_model,
        c(beta0 = beta0, gamma = gamma, mu = mu, k = k, tau = tau)),
    error = function(e) NULL
  )
  if (is.null(out)) return(1e12)

  predicted <- out$I + out$R + out$D
  sum((predicted - observed_cases)^2)
}

fit <- optim(
  par    = log(c(0.5, 0.1, 0.05, 0.01, 30, 5)),
  fn     = sird_objective,
  method = "L-BFGS-B",
  lower  = log(c(0.01, 0.01, 0.001, 0.0001, 1, 1)),
  upper  = log(c(5.0,  1.0,  1.0,   0.5,    200, 1000))
)

Four details are critical:

  • Log reparameterization: all parameters are fit on a log scale so proposals are automatically positive (all rates must be positive).
  • Bounds: the lower and upper arguments keep the optimizer in physically plausible parameter space.
  • Guard clause: if the proposed parameter set is unreasonable, the objective returns 1e12 — a value that the optimizer quickly learns to avoid.
  • tryCatch(): if ode() fails (which can happen at extreme parameter values), the objective returns the same large penalty rather than crashing.

7. Full-Fit and Projection Workflow

The model is fitted in three stages:

  1. Training: Fit β₀, γ, μ, k, τ to the first 80% of the observed data.
  2. Full fit: Re-solve over the entire observed window to compare the fitted curve against all observations.
  3. Projection: Anchor a new ode() call at the last observed state and integrate forward for 14 days, continuing the β(t) decay.

Anchoring at the last observed state is critical. If the projection simply continued from the model's fitted state, it could jump discontinuously at the boundary between data and forecast. Anchoring prevents this and guarantees visual continuity.

8. Practical Tips

  • Inspect the return object — NA rows indicate solver failure.
  • Wrap calls in tryCatch(), especially inside optim().
  • Always bound parameters to avoid unphysical estimates.
  • Normalize errors by the number of observations so RMSE and MAE are interpretable.
  • Hold out the last 20% of data for validation before trusting the projection.
  • Plot the fitted β(t) alongside the observed cases — if the intervention decay does not align with a visible slowdown in the data, the fitted parameters are not trustworthy.
