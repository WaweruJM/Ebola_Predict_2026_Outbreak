deSolve Package in R

Resource Library

Solving ODEs with deSolve

deSolve is the standard R package for solving initial value problems in ordinary differential equations. It provides a unified interface to a wide range of numerical solvers, including the widely used lsoda.

The Standard Pattern

  1. Define a function that returns the derivatives of each state variable.
  2. Set initial conditions and parameter values.
  3. Call ode() with the state, times, function and parameters.

The SIR Model in deSolve Syntax

library(deSolve)

sir_model <- function(time, state, parms) {
  with(as.list(c(state, parms)), {
    N  <- S + I + R + D
    dS <- -beta * S * I / N
    dI <-  beta * S * I / N - (gamma + mu) * I
    dR <-  gamma * I
    dD <-  mu * I
    list(c(dS, dI, dR, dD))
  })
}

state0 <- c(S = 19999990, I = 10, R = 0, D = 0)
params <- c(beta = 0.5, gamma = 0.15, mu = 0.05)
times  <- 0:100
out    <- ode(state0, times, sir_model, params)

The result is a data frame with one row per time point and one column per compartment.

Choosing the Right Solver

  • lsoda — the default. Auto-switches between stiff and non-stiff methods.
  • vode — variable-coefficient solver, good for long integrations.
  • ode45 — classic non-stiff Runge–Kutta.
  • radau — implicit solver for very stiff systems.

Calibration with optim()

deSolve only solves an ODE once you provide parameters. To estimate the parameters from data, we pair it with optim():

sir_objective <- function(par) {
  beta  <- exp(par[1])
  gamma <- exp(par[2])
  i0    <- exp(par[3])
  state0 <- c(S = 2e7 - i0, I = i0, R = 0, D = 0)
  out <- ode(state0, times, sir_model,
             c(beta = beta, gamma = gamma, mu = 0.05))
  predicted <- out$I + out$R + out$D
  sum((predicted - observed)^2)
}

fit <- optim(
  par    = log(c(0.5, 0.1, 10)),
  fn     = sir_objective,
  method = "L-BFGS-B",
  lower  = log(c(0.01, 0.01, 1)),
  upper  = log(c(5.0,  1.0,  1000))
)

The logarithmic transformation ensures that optim() always proposes positive parameter values — a requirement for all epidemiological rates.

Full-Fit and Projection Flow

  1. Fit the model to the training window using optim().
  2. Solve the ODE over the full observed window to evaluate fit against the test data.
  3. Anchor a new solve at the last observed state and integrate forward for the projection horizon.

Practical Tips

  • Always inspect the return object — if ode() silently returns NA rows, the parameters were too extreme.
  • Wrap the objective in tryCatch() so a failed integration returns a large penalty instead of crashing the fit.
  • Bound the parameters tightly to avoid unphysical estimates.
  • Normalise the sum of squared errors by the number of observations so RMSE and MAE are interpretable.
